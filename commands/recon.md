# recon — 调研任务派发协议

接收任意粒度的调研问题，智能判断是否拆分，生成带 `recon` 标签的调研任务 issue，供 `/cursor --label recon` 并行执行。**recon 只派发任务，不自己执行调研。**

## 使用方式

```
/recon <问题>           # 单个问题域 → 直接生成1个任务 issue
/recon <行业/赛道>      # 大范围 → 拆分成多个方向 → 确认后批量生成
```

---

## 执行协议

### Step 1 — 判断粒度

收到输入后，判断调研范围：

**单任务**（一个具体问题/竞品）：
- 示例：`/recon Duolingo定价策略`、`/recon Cambly用户口碑`
- 直接进 Step 3，生成 1 个 issue

**多任务**（一个行业/赛道/宽泛问题）：
- 示例：`/recon 英语学习AI赛道`、`/recon 中国英语教育市场`
- 进 Step 2，先列任务列表等确认

---

### Step 2 — 多任务：列出任务列表，等用户确认

输出格式：

```
识别到以下调研方向，共 N 个：

1. [调研对象A] — [一句话说明调研角度]
2. [调研对象B] — [一句话说明调研角度]
...

确认后批量创建 recon 任务 issue，然后 /cursor --label recon 并行执行。
确认吗？（回复「确认」或调整列表）
```

等用户确认后，进 Step 3 批量创建。

---

### Step 3 — 创建调研任务 issue

为每个调研对象调用 `mcp__github__create_issue`：

**title：** `🔍 [调研对象] 调研任务`

**label：** `recon`

**body 模板：**

```markdown
## 调研对象

[竞品名 / 方向名]

## 数据源

按优先级：
1. Web search — 搜索「[调研对象] + 功能/定价/用户评价」
2. Playwright — 抓取官网、App Store 页面
3. 手动补充 — 如有具体 URL 在此列出

## 分析框架（三维全跑）

### 维度1：功能对比
- 核心功能列表
- 与 TalkFlow 的差距（有什么我们没有 / 我们有什么更好）

### 维度2：用户口碑
- App Store / Play Store 评分 + 典型好评/差评
- Reddit、知乎、小红书用户真实反馈
- 核心吐槽点 + 核心亮点

### 维度3：商业模型
- 定价策略（免费/付费/订阅结构）
- 转化漏斗推测
- 收入规模（公开数据）

## AC（验收标准）

- [ ] 三个维度均有实质内容（非空）
- [ ] 功能对比有具体功能名称，不是泛泛描述
- [ ] 口碑有真实用户原话引用
- [ ] 商业模型有具体价格数字

## 执行完成后

在此 issue 添加 comment，格式：

## 调研报告
### 功能对比
[内容]
### 用户口碑
[内容]
### 商业模型
[内容]
### 对 TalkFlow 的启示
[2-3条可操作建议]
```

---

### Step 4 — 完成提示

所有 issue 创建完毕后输出：

```
已生成 N 个调研任务（label: recon）

→ /cursor --label recon    并行执行所有调研
→ 执行完成后查看 result-recon issue 汇总
```
